## 2026-07-05
**Topics:** Outline view scene sidebar, prose typography consistency (Editor/Outline), font-selector kill decision
**Did:**
- Built a scene-metadata + scene-text sidebar for the Outline view (`src/renderer/components/OutlineView.tsx`), replacing the old plain nav-list-only right rail. Clicking a scene's slug/title opens a metadata panel (title, character, chapter, word count, plus the same custom Properties fields Editor view uses); a "Preview" button opens a second panel to the right showing the full manuscript prose, editable, autosaving via the existing `onDraftChange` path.
- Exported `MetaRichField` and `CreatableMultiSelect` from `EditorView.tsx` instead of duplicating them, so the Outline sidebar's Properties editor is the same implementation as Editor view's, not a copy that can drift.
- Fixed a real CSS bug: the `33 | NOAH` slug was dropping above the scene title instead of staying inline whenever the title was long enough to wrap (`.ms-head` was `flex-wrap: wrap`, so the whole title item moved to a new line instead of just wrapping its own text). Fixed by making the row `nowrap` and letting the title flex-shrink into the remaining space.
- Widened the Outline text column from 600px → 880px (left-justified, explicitly not centered — flagged by Brian after I assumed centering was wanted when it wasn't).
- Added paragraph indent (`text-indent: 2em`) to actual manuscript prose only: Editor view's `.tiptap p`, and the Outline sidebar's scene-text preview panel. Explicitly not applied to Notes or the metadata Properties fields (not prose).
- Converted the Outline screen's own synopsis field from a plain `<textarea>` to a TipTap rich-text editor, specifically so it could get real per-paragraph indent too (a `<textarea>`'s `text-indent` only affects the very first line of the whole field, not each paragraph — there's no per-paragraph DOM to hang it on). Existing outline notes were stored as plain newline-separated text; added a one-time `legacyOutlineToHtml` conversion so old content displays correctly as paragraphs without any destructive migration — nothing in the database changes until a scene is actually edited again, at which point it naturally saves as HTML going forward. Verified `dataService.saveOutline` is just a plain string column with no format assumption, so this is safe.
- Found and fixed a font-size/family mismatch introduced along the way: the new scene-text preview panel used a different font token (`--font-reading-body`, 15px hardcoded) than Editor view's actual prose (`--font-body-size`, 16px). Same fix applied to the Outline screen's own synopsis field once it became rich text. All three prose surfaces (Editor, Outline preview panel, Outline synopsis) now share identical typography.
- Removed the "Tags" row from the metadata panel per Brian's ask.
**Decisions:**
- Brian's working theory, raised while building this: the sidebar is the key lever for the app's usability, since there are many "screens" (POV/Rails/Table/Editor/Notes/Outline/Tasks) and a novelist shouldn't have to click between them constantly. Wants a future "POV view" preview that opens in a sidebar from any screen so you can check/edit a character's scene lineup without leaving where you are. Captured in `STATUS.md` backlog as its own future design pass, deliberately not folded into today's single-screen work.
- Fonts are a mess project-wide (this session hit three separate token/size mismatches while just trying to make three prose surfaces consistent). Brian's call: kill the font selector rather than keep patching inconsistencies piecemeal. Added to `STATUS.md` Launch Critical Path as item 4 — scope not yet defined, needs a decision on what replaces per-note font choice first.
**Left off:** none blocking — Outline sidebar feature is functionally complete and verified in the running dev app (full-tier build). Font-selector removal scope is an open design question, not started.
